# numeric-lang v1.0.1

A patch release. There are no API changes.

## Fixed

- **Long floats with separators parse.** A float with `_` separators that was longer than 512 bytes once the separators were removed used to fail with `FloatTooLong`, while the same digits without separators parsed fine. Separated floats now parse at any length and give the same correctly rounded `f64` as the text without separators. The path still allocates nothing and works under `no_std`: a literal too long for the 832-byte stack buffer is rewritten in a shorter form with the same value before it reaches the standard library's parser. `FloatTooLong` is no longer returned; the variant stays so existing `match` arms compile.
- A long separated float with bad syntax now reports `MalformedFloat`, the same error as without separators.

## Documented

- A float outside the `f64` range is not an error. Like the standard library's parser, `parse("1e400")` gives `Float(inf)` and `parse("1e-400")` gives `Float(0.0)`. Integers are different: a value past `u128::MAX` is `Overflow`. Check `is_finite()` on the result if your language should reject an out-of-range float constant.

MSRV is unchanged at Rust 1.85.
